PACusage methods and rationale

PACusage finds polyadenylation site clusters (PACs) in 3′-end RNA-seq alignments, counts the reads at each one, and tests every treatment against its declared control for changes in how a gene's reads are shared among its PACs. This document goes through the pipeline in the order it runs. For each step it says what the step does, which defaults it uses, and why, with the statistical result, biological observation, or community standard behind the choice. Limitations and open questions for reviewers are collected at the end.

A

Design principles

Four rules shape the pipeline. Each later step follows from one or more of them.

Calibrate the protocol before calling any PAC

3′-end protocols place read ends differently relative to the cleavage site. Assays that keep the transcript–poly(A) junction report the site at nucleotide resolution. Oligo(dT)-primed tag protocols whose reads run toward the poly(A) tail, such as the forward-reading edition of QuantSeq (Moll et al., 2014), produce reads that end upstream of the site, with a protocol-specific spread, and PACusage's Plasmidsaurus profile treats that assay the same way. PACusage measures this behavior against annotated transcript ends in each run and uses the measured offset distribution, instead of assuming one.

Define the features once, freeze them, then count and test

One PAC atlas is built from all samples, annotated, checksummed, and frozen before any sample is counted or tested. Discovery never uses the treatment–control contrasts, effect sizes, or PAS motifs. Choosing features with the same contrast that is later tested inflates false positives (circular analysis, Kriegeskorte et al., 2009). Discovery does use condition labels in one symmetric way: a PAC must be supported by replicates within the condition that supports it. The project lead chose to keep this rule (Step 5; open question 1).

Compare each treatment only with its declared control

Every condition names its control in the sample sheet, and comparisons follow those links, including chains such as WT → disease_vehicle → disease_drug. Each test then isolates one intervention against the baseline it was designed against. There are no treatment-versus-treatment tests.

Infer from raw counts, interpret with PAU, and never add pseudocounts

The model is fitted to integer read counts. PAC usage (PAU) is reported for interpretation: a PAC's count divided by its gene's total in that sample. Pseudocounts pull low-count genes toward equal usage and distort effect sizes, so zeros are handled inside the model (Step 9) and never by editing the counts.

C

The pipeline at a glance

The steps run in this order. Alignment preparation, strandedness inference, the scan, and counting run per sample in parallel. Validation, calibration aggregation, discovery, and annotation run once. Modeling runs once per comparison family, and its bootstrap is split into batch jobs.

  1. 1Validate inputs
    Parameters, sample sheet, control graph, references, contigs, and R packages are checked before any heavy work.
  2. 2Prepare reference and alignments
    Link, index, or sort without touching sources. Hash every input.
  3. 3Layout and strandedness
    Detect SE or PE and infer the strand protocol from reads over unambiguous exons.
  4. 4Scan and calibrate
    Read each alignment once, filter reads, collect ends for every evidence source, and calibrate against annotated ends.
  5. 5Discover PACs
    Cluster exact boundaries, or find kernel-matched peaks for proximal tags, and require replicate support.
  6. 6Annotate and freeze the atlas
    Genes, PAS motifs, internal-priming flags, known sites, and a checksum.
  7. 7Count reads at PACs
    Recount every sample against the frozen atlas and compute PAU.
  8. 8Filter testable PACs
    Count and usage thresholds over the family's samples, blind to condition.
  9. 9Model differential usage
    DRIMSeq Dirichlet-multinomial fits, stageR stage-wise testing, zero-count stabilization, and bootstrap intervals.
  10. 10Call events
    PAC calls (gained, lost, increased or decreased usage), and each gene's dominant switch, active-PAC change, and APA pattern.
  11. 11Motif preference and k-mers
    A limma test of PAS-motif usage and an exploratory Cochran–Mantel–Haenszel k-mer scan.
  12. 12Figures, report, and provenance
    Treatment–control figures, a static HTML report, checksums, versions, and byte-identical reruns.

Step 1

Validate inputs

What it does

The first task validates every parameter once against the JSON schema, which defines each parameter's type, range, allowed values, and default. Later steps read the resolved file and never re-derive defaults. The same task checks the sample sheet, confirms that every file exists and can be read, and compares each alignment's contig names and lengths with the FASTA. The annotation must share contigs with the alignment. A separate job loads the R statistics packages at the same time, so a missing dependency stops the run within minutes, before any alignment is read.

The sample sheet rules:

  • Sample IDs are unique and filesystem-safe.
  • Each condition names one control, consistently across its samples. A genuinely empty control field marks a control condition.
  • Every named control exists, and every control is used by at least one treatment. A condition cannot name itself, and the control graph must be acyclic.
  • Each modeled condition has at least 2 biological replicates. With insufficient_replicates_policy: warn, the run continues as explicitly exploratory. Every affected comparison is then marked, and gained or lost calls are demoted to candidates.
  • Covariates named in model_covariates must be complete within each family, and they enter the model as categorical factors.

Why

  • On a cluster, an error found in the first minutes costs minutes. The same error found after the alignment scan costs hours.
  • Two replicates is the minimum for estimating between-replicate variability, which the Dirichlet-multinomial model needs (Step 9). In gene-level differential expression, power rises substantially with more replicates (Schurch et al., 2016), so fewer than two is allowed only as a labeled exploratory run.
  • An acyclic control graph gives every comparison one well-defined baseline.
  • Comparing contig names and lengths catches alignments made against a different build or naming scheme, which would otherwise fail silently or misplace reads. Contig name differences can be bridged with chromosome_aliases.

Step 2

Prepare reference and alignments

What it does

The FASTA must be uncompressed. It is symbolically linked into the task's work directory and indexed there with samtools faidx. An alignment whose header declares coordinate order (@HD SO:coordinate) is linked, not copied. Its existing index is reused if it opens and works; otherwise a new index is built in the work directory. Any other alignment is sorted into the work directory with samtools sort --no-PG and indexed. BAM stays BAM and CRAM stays CRAM.

Each source is hashed once (SHA-256), and its size and modification time are recorded. Every later step that reads an alignment checks both before and after its pass.

Why

  • The @HD SO tag is the SAM specification's declaration of sort order (SAM/BAM Format Specification Working Group). A coordinate-sorted BAM file can be indexed for fast retrieval of any region (Li et al., 2009), and samtools and htslib provide that indexing (Danecek et al., 2021).
  • Sources are often shared, read-only, or archived. htslib writes a missing .fai next to whatever path it is given, so the pipeline indexes a link inside the work directory, which guarantees that nothing is written next to the source.
  • Checksums tie every result to exact inputs, and the size and time checks catch a source being replaced mid-run.
  • --no-PG keeps the task's absolute path out of the sorted file's header, which reruns need in order to be byte-identical.

Upstream of the pipeline

Trimming, alignment, and duplicate handling happen before PACusage. The pipeline drops only reads already flagged as duplicates (SAM flag 0x400). For 3′ tag libraries, remove or flag duplicates only with UMIs, for example by deduplicating with UMI-tools (Smith et al., 2017). Many independent molecules end at the same 3′ position in a highly expressed gene, so duplicate marking by position alone removes genuine reads and flattens the signal the pipeline measures.

Step 3

Layout and strandedness

What it does

Layout (SE or PE) is detected from the flags of the first 10,000 records, or set by the user. A set layout must agree with the file, or the run stops.

Strandedness is inferred from a reservoir sample of up to 200,000 primary alignments (read 1 for paired data) that overlap exons of exactly one gene on one strand. Reads in antisense overlaps or multi-gene regions are skipped. At least 10,000 informative reads are required. The sample is called forward or reverse when at least 80% of reads agree, and ambiguous otherwise. An ambiguous call stops the run unless the strandedness is set by the user or the library profile. A strandedness set by the user or implied by a library profile is still compared with the inferred one, and a conflict stops the run. Reads on excluded contigs, which are the mitochondrial ones by default, are skipped here as well.

Why

  • Strand decides which end of a read is its 3′ end and which gene a PAC belongs to. A mislabeled library would place every PAC on the wrong strand.
  • The approach follows RSeQC's infer_experiment (Wang et al., 2012), which by default uses the first 200,000 usable reads over annotated genes. The 0.8 cutoff matches the default stranded threshold of the nf-core/rnaseq pipeline.
  • Reservoir sampling gives a uniform sample in one pass whatever the file order (Vitter, 1985), so the call is not dominated by the first chromosomes. The seed is fixed, so the call is reproducible.
  • Restricting to exons of a single gene on a single strand removes reads whose orientation can't be attributed to one transcript.

Step 4

Scan alignments and calibrate the protocol

What it does: the scan

Each alignment is read once for evidence. Together with the strandedness pass, that makes two full reads per alignment. The scan collects end observations for every evidence source the profile allows, so calibration can compare them without rereading the file.

  • Read filters. Unmapped, secondary, supplementary, QC-failed, and duplicate-flagged reads are dropped, as are reads with MAPQ below 20, reads on excluded contigs, and reads whose NH tag reports more than one alignment. Every exclusion is counted by reason.
  • Pairs. Paired data are name-collated once (samtools collate), and each pair counts as one fragment. Both mates must pass the filters, map to the same contig, and carry the proper-pair flag. No insert-size limit is applied, because spliced fragments can span long introns.
  • Coordinates. The 3′ end on the plus strand is the largest aligned reference end, and on the minus strand the smallest aligned start, in interbase coordinates. Soft-clipped bases do not extend the boundary.
  • Evidence sources. read_3p and read_5p are the transcript-oriented ends of the selected read. fragment_3p is the outer 3′ end of a proper pair. polyA_junction is the genomic boundary next to a terminal soft clip that looks like a poly(A) tail: at least 6 nt, at least 80% A.
  • Splice continuations. For proximal-tag runs, the scan also records reads that splice directly from one exon block to the next (CIGAR N), for the readthrough filter in Step 5.

Why

  • MAPQ is the phred-scaled probability that a read is misplaced (Li, Ruan and Durbin, 2008), so a MAPQ of 20 or more means an estimated misplacement probability of 1% or less. Aligners scale MAPQ differently, so the NH tag, which counts reported alignments, removes multimappers explicitly when the aligner writes it.
  • Counting one fragment per pair is the standard for paired-end counting, as in featureCounts (Liao, Smyth and Shi, 2014). Counting both mates would double-count molecules.
  • Name collation rebuilds pairs in a single streaming pass, which avoids random-access mate lookups in a coordinate-sorted file.
  • Soft-clipped bases are not aligned to the genome, so they cannot define a genomic boundary. An untemplated A-rich clip at the read end is direct evidence of the cleavage site, and it is kept as its own evidence source.

What it does: calibration

  • Calibration genes. These are genes whose annotated transcripts all end at one coordinate. A read end counts toward the nearest such end on the same strand, if it lies within 1,000 nt. A gene needs at least 2 such ends, and each sample needs at least 100 such genes.
  • Per-sample kernel. For each evidence source, read ends are tallied by offset from the annotated end, with positive offsets upstream. The histogram is smoothed once with weights [1, 2, 3, 2, 1] and normalized to sum to one.
  • Reproducibility. Each sample's kernel is correlated (Pearson) with the equal-weight mean of all the other samples' kernels. At least 0.8 is required.
  • Classification. A sample is exact when its median absolute offset is at most 2 nt, its central 90% interval (5th to 95th percentile) is at most 12 nt wide, and at least half its ends lie within 1 nt of the annotated end. It is proximal when the median offset is at least 3 nt upstream and the central interval lies within ±1,000 nt. Otherwise it is ambiguous.
  • Choice. The generic_3prime profile picks the evidence source with the best median correlation, and requires it to beat the runner-up by at least 0.1. The plasmidsaurus_3prime profile fixes read_3p. The exact_boundary profile uses polyA_junction when every sample has enough calibration genes for it, and otherwise fragment_3p for paired data or read_3p. Explicit settings fix the source or endpoint model, which must still pass the gene-count and reproducibility thresholds.
  • One model per run. All samples must resolve to the same profile, evidence source, and endpoint model, or the run stops and asks for separate runs.
  • Pooled kernel and diagnostics. The run's kernel is the equal-weight mean of the sample kernels. For proximal-tag runs, a warning is raised (the run continues) when the kernel, smoothed with a centered moving average as wide as δ* (rounded down to an odd width), has more than one separated mode, or when the median central interval is more than six times the kernel's minimum resolvable separation (defined in Step 5). A mode must reach a quarter of the highest one, and neighboring modes stay separate only if the valley between them falls below half the lower one.

Why

  • The offset distribution against known ends is the protocol's empirical point-spread function. Measuring it per run replaces a vendor or literature assumption with data, and exposes a library that does not behave as its label says.
  • Genes with a single annotated end make the true end unambiguous. Unannotated alternative ends near a calibration gene's end still add spread or extra modes, which is what the kernel diagnostics look for.
  • Leaving each sample out of the reference it is compared with prevents it from correlating with itself. Equal sample weight stops one deep library from defining the kernel for everyone.
  • A single frozen atlas needs a single resolution model. Libraries made with different chemistries have different point-spread functions, and a batch term cannot reconcile them, so mixed protocols must be analyzed separately.

Limit

Offsets are weighted by reads, so the most highly expressed calibration genes carry the most weight. Mitochondrial transcripts are single-end genes in standard annotations, extremely abundant, and packed end to end, and their 3′ ends are set by excising the tRNAs that flank them, the tRNA punctuation model (Ojala, Montoya and Attardi, 1981). They would therefore distort the kernel, so mitochondrial contigs are excluded by default (chrM, MT, chrMT, matched by alignment name or alias). That also keeps mitochondrial sites out of the atlas and the counts. A mitochondrial contig under another name, such as M, has to be listed or aliased.

Step 5

Discover PACs

The support rule, shared by both strategies

A candidate needs at least 10 reads in total. A sample supports it with at least 2 reads. The number of supporting samples must reach pac_min_supporting_samples (default 2) within at least one condition. A value between 0 and 1 is read as a share of that condition's samples, rounded up. Samples from different conditions cannot be combined to admit a candidate.

Why. Requiring agreement between biological replicates before calling a feature guards against sites created by one library's noise. Applying the rule within a condition lets condition-specific PACs, the ones that become gained or lost events, enter the atlas, while samples from unrelated conditions cannot jointly admit a site that no condition reproduces. The rule treats every condition the same way, and it uses no contrast, direction, or effect size. Open question 1 discusses its interaction with later testing.

Exact-boundary clustering

  • For every observed coordinate, the pipeline measures support within ±2 nt: the number of samples with reads there, the sum of per-sample counts capped at 3, and the raw count.
  • Seeds are ranked by supporting samples, then capped support, then raw support, then coordinate, so ties resolve deterministically.
  • The strongest unassigned seed claims every unassigned end within ±12 nt. This repeats until every end is assigned.
  • With a known-PAC BED (known_pacs), a candidate within 12 nt of a known site is kept with at least 5 reads, under the same support rule. It is labeled known_rescue_only and kept out of the motif and k-mer analyses.

Why. Cleavage for one poly(A) signal is heterogeneous, mostly within a few nucleotides but with a tail reaching tens of nucleotides (Pauws et al., 2001; Tian et al., 2005). A ±12 nt cluster spans 25 nt, in line with Tian et al. (2005), who merged cleavage sites lying within 24 nt of each other into one site. Ranking by the number of supporting samples before depth, and capping each sample's contribution at 3, keeps one deep library or PCR stack from creating a seed. Known sites from an independent atlas such as PolyASite 2.0 (Herrmann et al., 2020) justify a lower read threshold. Sites admitted that way are kept out of the motif tests, so prior annotation can't shape the motif results.

Proximal-tag peak discovery

  • δ*, the kernel's minimum resolvable separation, is the smallest shift at which the kernel's overlap with a shifted copy of itself, O(δ) = Σd min(K(d), K(d − δ)), falls to 0.5 or below.
  • Read ends are binned in transcript orientation at the smaller of 25 nt (proximal_bin_size) and δ*, and each sample's count at a position is capped at 3.
  • The binned signal is convolved with the binned pooled kernel (FFT-based) to give a matched score at every implied PAC position.
  • Local maxima of the score are ranked by score, then coordinate. A maximum closer than δ* to a stronger one is merged into it, and its position is kept in the PAC's list of merged maxima.
  • Each read end is assigned to a peak by kernel likelihood, with the rule used in Step 7. The support rule is then applied to the resulting counts.
  • Each PAC reports its representative coordinate, a region of width δ* around it, resolution_nt = δ*, and coordinate_precision: estimated.

Why. Correlating the signal with its known spread function follows the matched-filter principle (Turin, 1960), with the calibrated kernel as the known shape. The classical optimality result assumes additive white noise, which read counts are not, so here the score is a well-motivated heuristic rather than an optimal detector. Capping per-sample counts limits the influence of any one library. Two sites whose spread functions overlap by more than half are treated as unresolvable, an overlap-based resolution criterion, so closer maxima are reported as one PAC with its region. PAS motifs are never used to place or select proximal-tag PACs, which keeps the motif-preference test in Step 11 from being circular.

Reads that end inside a spliced transcript (proximal-tag runs only)

Both filters look at a candidate's read pile, which lies upstream of the candidate by the kernel's peak offset: a sharp pile of read ends peaks that many bins downstream of it.

  • Internal exon ends. A candidate within one bin of where a pile at an annotated internal exon's 3′ end would peak is rejected. The donors are the 3′ ends of exons that a transcript splices onward from, except those within two bins of any transcript's end, so a real end there is never rejected.
  • Readthrough. A candidate whose pile lies in an exon block that reads splice directly onward from is rejected when, in every condition whose replicates support the candidate, those splice reads pooled over the condition's samples number at least 2.

Why. A read that crosses a splice junction, but whose short overhang into the next exon is not aligned, ends at the donor, so internal exon ends collect sharp artifact peaks, and in 3′ tag data these are near the transcript's 3′ end. Oligo(dT) also primes internally at A-rich sequence inside transcripts (Nam et al., 2002). If reads splice out of an exon into the next one in every condition that has the candidate, that exon is not a transcript end there, and a tag cluster inside it is more likely an artifact than a PAC. A supporting condition without splice reads keeps the candidate, since the exon may end there. Conditions that lack the candidate are not consulted: at low coverage they would otherwise protect every artifact. Intronic sites away from exon edges are not inside spliced exon blocks, so neither filter touches them.

Step 6

Annotate and freeze the atlas

What it does

  • Gene assignment, on the same strand, in this order: a terminal exon, then another exon, then an intron, then downstream of a gene's end within 5,000 nt, then intergenic. Downstream assignment goes to the nearest same-strand gene end upstream of the PAC, so no other gene can lie between them. Containment is inclusive (start ≤ c ≤ end), because in interbase coordinates a 3′ boundary equals its exon's end. When more than one gene qualifies at the chosen level, the PAC is ambiguous: it stays in the atlas and is never tested.
  • Terminal and last exons. A transcript's final exon counts as a terminal exon unless it overlaps an internal exon of another transcript of the gene, as the final exons of retained-intron and 3′-incomplete models do, or it is a single-exon model apart from every exon of the gene's multi-exon transcripts, such as a fragment inside an intron. PACs in such exons count as internal-exon PACs. The atlas records each PAC's gene region (gene_region): last_exon, internal_exon, intron, downstream_of_gene, or intergenic. A gene's terminal exons that overlap form one last exon. The atlas records each last-exon PAC's last exon (last_exon_locus), and a PAC downstream of a gene gets the gene's 3′-most last exon.
  • Gene names come from one name per gene: its gene record's name, else the first name on its other records, else its ID. An ambiguous PAC lists its genes' names in the order of their IDs.
  • PAS motifs are searched from 50 to 5 nt upstream, and flagged when they fall in the core window from 35 to 10 nt. The built-in catalog has the canonical AATAAA, its common variant ATTAAA, and eight other variants: TATAAA, AGTAAA, AAGAAA, AATACA, CATAAA, GATAAA, AATATA, and AATAGA. The primary motif is the highest-priority match, preferring a copy in the core window and nearest 20 nt upstream. All matches are kept. The catalog can be replaced with pas_motif_catalog.
  • Internal priming is flagged when the 20 nt downstream of the PAC contain a run of 7 or more A's or are more than 60% A. The flag does not remove the PAC.
  • Known sites are matched within 12 nt. A known-PAC BED record's site is its 3′ edge in transcript orientation: end on the plus strand, start on the minus strand.
  • Confidence is low for an ambiguous gene or an internal-priming flag. It is high for a match to a known site with at least 2 supporting samples, and moderate otherwise, including rescued sites.
  • PACs are ranked proximal to distal within each gene. The atlas is then written, checksummed, and frozen. Its checksum seeds every random step downstream.

Why

  • The assignment order follows where functional PACs usually lie. Tandem 3′ UTR sites in terminal exons are the most common form of APA. Sites in internal exons and introns produce alternative last exons and truncated transcripts (Tian and Manley, 2017). Intronic polyadenylation is a regulated outcome in its own right, suppressed for example by CDK12 (Dubbury, Boutz and Sharp, 2018), so intronic PACs are kept as a class instead of being discarded.
  • Reference annotations such as GENCODE include retained-intron and 3′-incomplete transcript models, whose final exons are not transcript ends. Counted as terminal exons, they would create false last exons, and an intronic change would read as an alternative-last-exon or UTR change.
  • Annotations often end 3′ UTRs short, and extended 3′ UTRs are widespread, especially in the brain (Miura et al., 2013). The 5 kb downstream window captures many of these, and the nearest-gene rule stops a PAC from being assigned past another gene.
  • The canonical hexamer lies 10 to 30 nt upstream of the cleavage site, a median of 21 nt (Tian et al., 2005; see also Proudfoot, 2011). AATAAA and ATTAAA account for most sites in human (Beaudoing et al., 2000) and in human and mouse (Tian et al., 2005), and single-nucleotide variants account for much of the rest. The windows and priorities follow those observations.
  • Downstream A-rich sequence is the classic signature of internal oligo(dT) priming (Nam et al., 2002). Flagging instead of removing keeps the decision visible: gained and lost calls require no flag (Step 10), and reviewers can see how many flagged sites take part in other results.
  • Freezing and checksumming the atlas before counting fixes the feature set, gives it a version, and makes every downstream result traceable to it.

Step 7

Count reads at PACs

What it does

  • Every sample's ends are recounted against the frozen atlas.
  • Exact-boundary: each end goes to the nearest PAC within 12 nt, with ties to the lower coordinate. Ends farther away stay unassigned.
  • Proximal-tag: for each end, the likelihood of each nearby PAC is the pooled kernel's weight at the offset that PAC implies. The end is assigned to the most likely PAC only when that likelihood is at least 3 times the next best. Otherwise it is ambiguous, is not counted, and is reported per sample.
  • Counts stay integers. Gene totals use only PACs with one unambiguous gene. PAU = count / gene total, and is missing when the total is zero.
  • Three invariants are checked for every sample: accepted fragments equal assigned plus unassigned, PAC counts sum to gene totals, and PAU sums to one for every gene with reads.

Why

  • The Dirichlet-multinomial likelihood (Step 9) needs integer counts, so fractional allocation of ambiguous reads, as expectation-maximization would produce, is not an option.
  • With equal prior weight on two candidate PACs, a likelihood ratio of 3 means a posterior probability of at least 0.75 for the chosen one. Weaker evidence is left unassigned instead of guessed.
  • The assignment rule depends only on positions and the pooled kernel. It is identical for every condition, so it cannot create a difference between conditions.

Step 8

Filter testable PACs and genes

What it does

Each comparison family is filtered on its own samples.

  • A PAC needs at least 5 reads and reads in at least 2 samples, counted over the family's samples regardless of condition.
  • It also needs at least 1% of its gene's reads in as many samples of the family as its smallest condition has, from any of its conditions. A sample counts only when the gene has at least 10 reads in it. min_site_usage_dropouts (default 0) lowers that count to allow for bad replicates, never below 2, or below the smallest condition if it has fewer.
  • A gene needs at least 20 reads and at least 2 PACs that pass.
  • PACs with no gene or an ambiguous gene are never tested.
  • Every PAC gets a row in statistics/FAMILY.statistical_filtering.tsv.gz: tested, or the reasons it was not.
  • After the family fit, a comparison tests a gene only when its control and its treatment each have at least 2 samples (or all of a smaller group) with at least 10 reads at the gene's tested PACs; min_group_gene_cpm (off by default) can also require a minimum CPM in those samples. The genes it skips are listed in statistics/CONDITION_vs_CONTROL.genes_without_depth.tsv.gz, as turned off or on when one group has no reads where the other's expression would have shown it, or as too low to test.

Why

  • Removing low-abundance features before a DTU test helps. It improved FDR control with little or no loss of power for DEXSeq (Soneson et al., 2016), raised DRIMSeq's power without a strong rise in FDR (Nowicka and Robinson, 2016), and, as minimum count and proportion filters, improved FDR and overall FDR (OFDR) control for both (Love, Soneson and Patro, 2018). PACusage filters the same quantities as the dmFilter settings of that workflow, PAC reads, PAC share, and gene reads. The workflow asks for 10 reads and a 10% share in at least as many samples as the smallest group, and 10 reads at the gene in every sample. PACusage's share rule is the workflow's, at a 1% default share; its read thresholds are more lenient and pooled over the family.
  • A share pooled over the family dilutes a site used in one condition, more so the more conditions share the control, and a share in one sample can be noise. Every condition has at least as many samples as the smallest, so a site used throughout any one condition passes however many conditions share the control, while a site that reaches the share in fewer samples, such as one noisy sample, does not.
  • The filters use the condition sizes but never which sample belongs to which condition, so permuting the labels leaves them unchanged. Under a null where the labels are exchangeable, they are then independent of any statistic computed by permuting labels, and approximately independent of the Dirichlet-multinomial test. That is the condition under which filtering leaves type I error control intact, and it can then raise power (Bourgon, Gentleman and Huber, 2010). Their exact results cover simpler cases: the overall mean or variance with a t-test under normality, and any permutation-invariant filter with the Wilcoxon test. In simulation at a threshold of 10% with a minimum change of 0.05, the filter admitted 60% to 65% of null PACs at 8% usage, and 5% to 8% of those had p ≤ 0.05 against a nominal 5%. With 100 shifted genes among 500, 2% to 9% of the treatment's gene calls were false, and null genes that kept a borderline PAC were called about as often as the others. Those genes had p ≤ 0.05 a little more often than genes that dropped the PAC, about 6.5% against 3.7%, but within each depth and precision stratum the two rates agree: the filter keeps fewer of the deep, precise genes, whose null p-values are rarely small.
  • A dropout allowance keeps the filter blind, since it also uses only condition sizes, but it is more lenient than standard practice at small replicate numbers: the DRIMSeq workflow and edgeR's filterByExpr ask for the full smallest group, and edgeR relaxes that only when every group has more than 10 samples, keeping at least 70% of the smallest group. In the same simulation with one dropout allowed, 5% to 7% of the admitted borderline null PACs had p ≤ 0.05.
  • Filtering per family means a PAC is judged on the samples in its own test, not on unrelated conditions.
  • A nearly silent group's handful of reads would otherwise read as a large shift in usage. The depth rule reads the condition labels, but only per-sample gene totals, never how they split among PACs; the Dirichlet-multinomial test conditions on those totals, so under the null the rule is independent of the test (Bourgon et al., 2010), and the genes kept keep their p-values. In simulation, 71% to 74% of genes whose treatment had a few reads at an even split would have had p ≤ 0.05; none is tested now, and the null genes kept stay calibrated.

Step 9

Model differential PAC usage

The model

For gene g with Kg PACs and sample s, DRIMSeq fits the Dirichlet-multinomial model of Nowicka and Robinson (2016) in the regression form that the package added in version 1.3.3, after that paper:

y_gs | p_gs ~ Multinomial(n_gs, p_gs) p_gs ~ Dirichlet(κ_g · π_gs) design: ~ model_covariates + condition (control = reference level)

πgs is the expected usage and κg is a gene-level precision shared across conditions. Lower precision means more variation between replicates than the multinomial allows. One model is fitted per comparison family, so the control and the precision are estimated from all of the family's samples. Covariates are categorical, and a rank-deficient (confounded) design stops the run with an explanation.

Precision uses DRIMSeq's defaults. The profile likelihood is Cox–Reid adjusted (Cox and Reid, 1987; McCarthy, Chen and Smyth, 2012), and a starting common precision is estimated from a seeded random 10% of genes. Gene-wise estimates are then moderated toward a trend in mean expression, with a prior weight that DRIMSeq estimates from the genes whose likelihood peaks at the upper end of its precision grid, as a function of mean expression when more than 100 genes do. When ten or fewer genes peak there, no weight can be estimated and DRIMSeq falls back to its default weight of zero, which leaves the gene-wise estimates unmoderated. Families with thousands of genes are normally moderated; the 40- and 60-gene simulated families in section D were not.

The tests

  • Family omnibus: a likelihood-ratio test of all condition coefficients at once. It is reported for description only and gates nothing.
  • Per comparison: the treatment's own coefficient is tested. The gene-level Dirichlet-multinomial likelihood-ratio test is the screen. DRIMSeq's PAC-level beta-binomial tests, each PAC against the rest of its gene, are the confirmation.
  • Gene FDR: Benjamini–Hochberg over the comparison's genes (Benjamini and Hochberg, 1995), threshold gene_fdr = 0.05.
  • PAC FDR: stageR's dtu stage-wise procedure at site_fdr = 0.05 (Van den Berge et al., 2017). The screen is a BH step over genes. Within screened genes, PACs are confirmed with an adjusted Holm–Shaffer procedure (Holm, 1979; Shaffer, 1986) at a level scaled by the share of genes that passed. A usage change needs at least two PACs to move, so the first two PACs share one correction. A two-PAC gene that passes the screen therefore has both PACs confirmed, with pac_fdr 0 by construction; for such genes the gene screen is the whole test.
  • A PAC is significant when its gene passes gene_fdr and the PAC passes site_fdr. The correction family is one declared treatment–control comparison. No correction is made across comparisons.

Why

  • The Dirichlet-multinomial models the relative usage of features within a gene while allowing for overdispersion between biological replicates (Nowicka and Robinson, 2016). A plain multinomial has no term for replicate variability, so it understates the variance of overdispersed counts.
  • Modeling proportions separates APA from expression: scaling all of a gene's counts leaves the usage test unchanged. The simulations check this (check S5 in section D).
  • Screening genes and then confirming features within them controls the gene-level FDR while still naming the PACs that changed. It respects the constraint that a gene's usage sums to one, which testing each PAC in isolation ignores. The differential transcript usage workflow of Love, Soneson and Patro (2018) applies stageR's screening and confirmation after either DRIMSeq or DEXSeq; PACusage uses it after DRIMSeq.
  • Each treatment's PAC calls rest on that treatment's own gene-level test, so significance for the family as a whole never carries over to a treatment.
  • Moderating precision shares information across genes, the standard remedy for unstable gene-wise dispersion with few replicates. It applies only when DRIMSeq's data-estimated prior weight is positive (see above).

Genes with a group without reads

A gene is a boundary gene when its unmodified fit is non-finite anywhere, or when a PAC has no reads across all samples of a condition or covariate level. The maximum-likelihood usage then sits at exactly zero, and the likelihood-ratio test is not defined there. For these genes:

  • Zeros are replaced with draws from U(0, 0.1), DRIMSeq's documented add_uniform rule, seeded from random_seed, the atlas checksum, the family, the gene, and the repeat number.
  • Precision, the full model, and every null model are fitted to the same perturbed counts, using the unmodified fit's common precision. DRIMSeq's own flag is not used, because dmTest would refit the null model to the original counts.
  • The fit is repeated 5 times. Medians of proportions, precision, and likelihood ratios are written back, and p-values come from the median likelihood ratio. At least 80% of repeats must succeed.
  • A PAC is flagged zero_boundary_unstable and left untested when its effect changes sign beyond ±0.001, fewer than 80% of fits converge, or its change in PAU spans more than 0.02 across repeats.
  • A condition with no reads at all for a gene leaves that gene untested in every comparison using that condition, which lists it in genes_without_depth; the family-wide test marks it group_without_counts.
  • Perturbed values never appear in any count or PAU output.

Why. This is DRIMSeq's own remedy for the boundary case, applied consistently to the full and null fits. Repeating it shows whether a result depends on the random perturbation, and unstable results are flagged instead of reported.

Bootstrap intervals for the change in PAU

For genes that pass the screen, and for gained or lost detection candidates (included because dm_bootstrap_include_candidates defaults to true), counts are simulated from the fitted Dirichlet-multinomial at each sample's observed total and design row. Proportions are refitted with each gene's precision fixed at the family estimate, zeros are perturbed as in the family fit, and the change in PAU is recomputed for every comparison of the family from the same draw. There are 200 replicates, seeded per gene and replicate so that results do not depend on batching or worker count. Intervals are the 2.5th and 97.5th percentiles, and are reported only when at least 80% of replicates succeed.

Why. A parametric bootstrap from the fitted model is a standard route to an interval for a derived quantity that has no closed-form variance (Efron and Tibshirani, 1993).

Limits

  • For stabilized genes, precision and p-values can move by orders of magnitude with a different seed, while the change in PAU barely moves. Read them with model_status = fitted_with_zero_count_stabilization. Seeds are fixed, so reruns reproduce them exactly.
  • Intervals are conditional on precision and so omit its uncertainty. In the current simulation they covered the true change in 85% of cases at a nominal 95% (section D), measured with 100 replicates in a 60-gene family whose precision was unmoderated. The figure moves with the seed; across earlier seeds it ranged from 80% to 93%. At the default of 200 replicates, each percentile endpoint rests on about 5 draws in its tail. At least 1,000 replicates is the usual recommendation for percentile intervals (Efron and Tibshirani, 1993). Treat the intervals as approximate.

  • Requiring both significance and a minimum effect focuses calls on shifts large enough to matter biologically. The minimum of 0.1 (10 percentage points of a gene's reads) is the project's chosen threshold, set with min_abs_delta_pau.
  • The label is "gained" rather than "de novo". No reads in the control means the site is not detectably used at this depth; it does not show that the site is absent.

Each gene in a comparison also gets an apa_pattern in the .genes table, from where its usage moved. PACs in introns or internal exons form the gene's upstream region. Step 11

Motif-class preference and exploratory k-mer enrichment

Motif preference: what it does

  • The gene set is fixed before any test: genes with at least 20 reads (min_gene_total) in every sample of the run. Rescued sites are removed, usage is renormalized over the remaining PACs, and a gene needs at least 2 of them.
  • For each sample and each primary motif (each catalog hexamer, and "no motif"), the score is the average, over genes that have a PAC with that motif, of the share of the gene's reads at those PACs. Every gene counts equally.
  • The same scores are also built for each motif class (canonical, the common ATTAAA variant, other variants, and no motif), pooling the hexamers of a class within each gene. Both are tested: one table per primary hexamer (.preference) and one per class (.preference_class).
  • Scores are transformed with asin(√score). One limma model (Smyth, 2004; Ritchie et al., 2015) is fitted per family on the main model's design, covariates included. Each treatment coefficient is tested, with BH adjustment across motifs within the comparison.
  • A motif is tested in a comparison only when every sample in it has at least 50 informative genes for that motif.
  • A sensitivity table repeats the summaries with rescued sites included. It is descriptive only.

Why

  • Poly(A) signal strength shapes site choice. Distal sites carry the canonical hexamer more often than proximal ones (Tian et al., 2005), and changes in core 3′-processing factors shift usage between strong and weak sites (Tian and Manley, 2017). A shift toward PACs with a given motif therefore points to a mechanism.
  • Equal gene weight stops a few highly expressed genes from dominating the score. The condition-blind gene set avoids selecting genes on the outcome being tested.
  • The arcsine square root is the classical variance-stabilizing transform for binomial proportions, which Anscombe (1948) refined by adding 3/8 to the count and 3/4 to the total. The plain form used here accepts exact 0 and 1 without pseudocounts. limma's moderated t-statistic borrows variance information across the motif rows. With about ten rows that moderation is weak, so the test is close to an ordinary linear-model t-test.
  • Using the main model's design keeps the covariate handling consistent between the usage and motif tests.

k-mer enrichment: what it does

For each comparison, the event PACs are those called gained or increased usage. The background is every other PAC of the same genes that was tested in that comparison, excluding rescued, ambiguous, and unassigned PACs. Each 6-mer's presence or absence in the upstream sequence (50 to 5 nt) forms one 2×2 table per gene. Genes are kept only if they have both event and background PACs and the k-mer varies within them. A Cochran–Mantel–Haenszel test combines the genes (Mantel and Haenszel, 1959). It reports the common odds ratio with a 95% interval from the Robins–Breslow–Greenland variance (Robins, Breslow and Greenland, 1986) and a χ² p-value without continuity correction, with BH adjustment across k-mers.

Why. Stratifying by gene compares PACs within the same gene, which controls for gene-level sequence composition and expression. The CMH test is the standard for a common association across many 2×2 strata. The Robins–Breslow–Greenland variance stays consistent both with many sparse strata and with a few large ones, which suits many genes with few PACs each. The analysis is labeled exploratory because PAC position (proximal versus distal) and event selection can confound sequence effects.

Figures, report, and provenance

What it does

  • A self-contained HTML report that works offline shows preparation actions, read exclusions, strandedness, calibration and kernel warnings, discovery and annotation summaries, filtering, model status, stabilization and bootstrap summaries, events, the treatment–control figures, and per-gene plots of mean observed PAU per condition for the genes with the most reads. The PAU sample correlation table and the PAU principal-component figure use the genes with at least 20 reads in every sample, and their PACs observed in every sample, with no zero-filling.
  • Figures are drawn with ggplot2 (Wickham, 2016) from the statistics tables, as PDF and PNG in figures/, and the report embeds the PNGs. Each comparison gets three: a volcano plot of each tested PAC's change in fitted PAU against its PAC-level p-value; each tested gene's distal PAC, with its fitted usage in the control against the treatment, colored by the gene's APA pattern; and the genes with a shift, each counted once, by the gene regions their usage moved from and to, proximal shifts left and distal right, with the same rows in every comparison. Six more cover all comparisons: the genes by their PAC calls, each counted once, and the gene events, above the genes per APA pattern, counted with all tested PACs and apart by whether the pattern needs PACs flagged for possible internal priming; each PAC's change in PAU against the reads at its gene in the less-covered group; a grid of the genes with an APA pattern in two or more comparisons, at most 50, with a table of every tested gene's pattern in each comparison; for each pair of comparisons, the change in PAU of every PAC tested in both, with Pearson r, drawn as up to 15 panels in a matrix, each pair once below the diagonal, and as a matrix of r across all pairs; and the samples on the first two principal components of observed PAU, with each PAC centered across samples and each component's sign set so its largest loading is positive. These put each comparison's own results side by side and add no test between treatments. The figures draw the calls in the tables and make none of their own. The distal PAC is the gene's most 3′ tested PAC in a last exon or downstream of the gene, and its direction, distal up or down, is that PAC's own confirmed call. Both plots label at most 20 genes on each side by gene name. The volcano plot labels each gene once, at the PAC its usage moved to, or at the one it left when only that side has a confirmed call, the most significant first and the larger change first among equal p-values. The distal-usage plot labels the largest changes. ggrepel (Slowikowski, 2026) moves the labels clear of each other, from a fixed seed and with no time limit, so reruns place them the same way.
  • Every table with one row per PAC starts with the same identity columns: pac_id, gene_id, gene_name, chrom, start, end, strand, and locus. Gene-level tables start with gene_id and gene_name. The remaining columns run from the answer to the evidence: comparison and call, then effect, significance, annotation, the data behind the call, and model diagnostics. The atlas BED scores are capped at 1000, the BED maximum.
  • The manifest/ folder records the resolved parameters, the normalized sample sheet, SHA-256 checksums of every input, the software versions (Python, pysam and htslib, R, DRIMSeq, stageR, limma, BiocParallel, ggplot2, and ggrepel), and a run manifest with the PACusage version and a checksum of the parameters. The atlas checksum is in atlas/pacs.v1.sha256.
  • Published gzip files and PDFs carry no timestamps, and every random step is seeded from random_seed, the atlas checksum, and its context. A fresh rerun with the same inputs and software reproduces every published file byte for byte. The only exception is Nextflow's own execution reports in pipeline_info/, which record the run's times.
  • Execution uses Nextflow (Di Tommaso et al., 2017), in its DSL2 syntax, with an Apptainer (formerly Singularity) image (Kurtzer, Sochat and Bauer, 2017) on Slurm. A task that exits with status 137, 140, or 143, which schedulers commonly return when they stop a task for exceeding its memory or time, is retried up to twice, with memory and time multiplied by the attempt number.

Why

The volcano plot uses the raw PAC p-value, because the stage-wise PAC FDR exists only in genes that pass the screen and is exactly 0 in screened two-PAC genes. The distal PAC's share of its gene's usage is a gene-wide analogue of the percentage of distal polyA site usage index (PDUI) of DaPars (Xia et al., 2014), which compares only a gene's distal and proximal 3′ UTR isoforms. The distal PAC's direction is its own confirmed call, so it carries stageR's error control, and the colors show whether a fall came from a tandem site or an intron. With three or more PACs, losing a middle PAC raises the distal share, so a distal rise does not always mean a longer 3′ UTR. Splitting shifts by gene region separates tandem 3′ UTR changes from shifts to intronic sites, such as the intronic polyadenylation that follows CDK12 loss (Dubbury, Boutz and Sharp, 2018). Counting each gene once by where its usage moved, and which way, shows whether a treatment favors proximal or distal sites. Counting PACs cannot show this, because every shift adds a gain and a loss. The coverage figure shows whether calls gather in poorly covered genes, where PAU estimates are least stable.

Two comparisons against the same control share that control's estimate, so their changes in PAU correlate positively even without shared biology. Chained comparisons, where one's treatment is the other's control, are fitted in different families but estimate the middle condition from the same samples, with opposite signs, so they correlate negatively. The concordance table therefore records each pair's relation, and r is read with it. The principal components are a check on the samples rather than a test: replicates should sit together, and a sample far from its condition points to a problem before any comparison is read. The components use observed PAU without zero-filling, because a gene without reads in a sample has no usage there.

A workflow manager, a fixed container, recorded checksums and versions, a parameter schema of the kind nf-core pipelines use (Ewels et al., 2020), and seeded randomness together let a reviewer rerun the analysis and get the same files. The integration test checks the byte-identical rerun on every change.

E

Limitations and open questions for reviewers

  1. Discovery uses condition labels. A PAC must be supported by replicates within the condition that supports it, a rule the project lead chose to keep. This selection is not independent of the later between-condition test under the null: a PAC whose support happens to concentrate in one condition is more likely to be admitted and to look different. The simulations start from count tables, so the end-to-end false-positive rate including this selection has not been measured. Is the trade-off (condition-specific PACs can be discovered, but selection is mildly outcome-dependent) acceptable, or should a pooled, label-blind support rule be offered?
  2. Error control at small n. At 3 to 4 replicates, null gene p-values fell at or below 0.05 in 7.5% of genes, and the PAC-level false discovery proportion was 8.3% at a nominal 5%. Precision is shared across conditions, so a treatment that changes replicate variability could worsen this. Precision moderation is estimated from the data and can fall back to none in small families (Step 9).
  3. Stabilized genes. Their p-values are seed-sensitive (Step 9). Results rest on DRIMSeq's documented add_uniform remedy, applied five times.
  4. APA patterns rest on the annotation. A final exon that another transcript of the gene splices through counts as internal. That treats a composite terminal exon correctly, as intronic polyadenylation, but it also demotes a canonical last exon that a minor isoform continues past. In such genes a tandem 3′ UTR change reads as an intronic pattern. A single-exon model lying 3′ of a gene's spliced transcripts is excluded, so a PAC in it counts as upstream region. An intronic single-exon model that overlaps a retained-intron transcript's final exon is kept, and can form a false last exon. Switches to unannotated last exons read as intronic changes, and genes annotated without transcript IDs cannot show alternative last exons. When usage moves into or out of the main last exon, a within-exon change in the same direction cannot be confirmed by a call, so it appears only in delta_utr_distal_share.
  5. Interval coverage. The bootstrap is conditional on precision. It keeps its default of 200 replicates for this release, a lead decision to be revisited. Coverage was 87% at a nominal 95% in the current simulation, which used 100 replicates in a 60-gene family, and 80% to 93% across earlier seeds.
  6. Readthrough filter. A real site whose reads end inside an exon that every supporting condition splices onward from, within about one read length of the donor, is rejected with the artifacts. This mostly affects internal-exon sites used by a minority of transcripts. Sites further into the intron are not affected.
  7. Proximal-tag resolution. Sites closer than δ* are merged. Reads that fall between two resolvable PACs without a 3-fold likelihood margin are discarded. That biases the absolute PAU of closely spaced PACs, equally in every condition. The PAS scan and internal-priming windows are measured from an estimated coordinate whose uncertainty is on the order of δ*.
  8. Calibration weighting. The kernel is read-weighted and depends on the annotation's single-end genes. Unannotated alternative ends near annotated ones broaden it, and the diagnostics warn but never stop a run. Mitochondrial contigs are excluded by default only under their common names (Step 4).
  9. PAS catalog. The built-in catalog has ten hexamers. Other reported variants, such as ACTAAA, AAAAAG, and AATGAA, are not included by default, but can be supplied with pas_motif_catalog.
  10. Internal priming is a flag. Flagged PACs are tested and can take part in increased and decreased usage calls, though not in gained or lost calls.
  11. Motif preference unit. Motif preference is tested per primary hexamer and per class. Rarer hexamers have fewer informative genes, and with about ten rows, or four classes, limma's moderation adds little. Warton and Hui (2011) argue against the arcsine transform for proportions in general, preferring logistic regression for binomial counts and the logit transform otherwise. Here the response is a gene-averaged usage, not a binomial count, and it can be exactly 0 or 1, where the logit is undefined without an offset.
  12. Multiple comparisons. FDR is controlled within each treatment–control comparison. Nothing is corrected across comparisons.
